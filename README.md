# Kookmin OTP Autofill

국민대학교 포털(ON국민포털) 로그인 시 메일로 오는 OTP 인증번호를 읽어 OTP 입력칸에 자동으로 채워주는 Chrome 확장 프로그램입니다. Gmail과 Naver 메일을 지원합니다.

> **비공식 도구입니다.** 국민대학교 및 Google, Naver와 관련이 없으며, 사용에 따른 책임은 사용자에게 있습니다.

## 동작 방식

1. 포털 OTP 화면(`https://portal.kookmin.ac.kr/por/otp`)이 열리면 확장이 동작을 시작합니다.
2. 60초 동안 3초마다, 지정한 Gmail 라벨 / Naver 메일함의 **안 읽은 메일 중 최신 2개의 제목**을 확인합니다.
3. 제목이 `[ON국민포털] 인증번호 안내 123456` 형식이고 **OTP 화면을 연 뒤에 도착한 메일**이면 번호를 입력칸에 채웁니다.
4. 그 사이 더 새로운 OTP 메일이 오면(예: 재전송) 새 번호로 바꿔 채웁니다. 사용자가 직접 입력하면 즉시 멈춥니다.
5. 확인 버튼은 누르지 않습니다. 직접 눌러야 합니다.

## 보안

- **외부 서버 없음.** 확장은 Gmail / Naver 메일과 포털 외의 곳으로 요청을 보내지 않습니다. 권한은 [`manifest.json`](manifest.json)에서 확인할 수 있습니다.
- **비밀번호 저장 없음.** 브라우저에 로그인된 메일 세션을 사용합니다. 확장 코드는 쿠키를 읽을 권한(`cookies`)이 없고, 쿠키 값을 볼 수 없습니다.
- **필요할 때만, 필요한 만큼만 읽음.** OTP 화면에서만 동작하고, 메일 본문은 읽지 않으며, 제목도 최신 2개만 봅니다.
- **저장하는 것은 설정뿐.** 메일 제목이나 OTP 번호는 저장하지 않습니다. 설정(라벨/메일함 이름, Naver 아이디)은 이 브라우저(`chrome.storage.local`)에만 저장됩니다.
- **로그에 민감정보 없음.** 디버그 로그에는 메일 개수, 경과 시간 등만 남고 번호·제목은 남지 않습니다.

### 주의

- 같은 PC에서 OTP까지 자동 입력되므로, 이 브라우저를 쓸 수 있는 사람은 2차 인증을 통과할 수 있습니다. **공용 PC에서는 사용하지 마세요.** (이미 같은 브라우저에서 메일에 로그인되어 있다면 위험도는 기존과 크게 다르지 않습니다.)
- Gmail은 Atom 피드, Naver는 메일 웹페이지가 쓰는 내부 주소를 사용합니다. **둘 다 공식 API가 아니므로** 메일 서비스가 바뀌면 동작하지 않을 수 있습니다. 이 경우 OTP를 찾지 못할 뿐, 다른 동작을 하지는 않습니다.

## 설치

1. 이 저장소를 내려받아 압축을 풉니다.
2. Chrome에서 `chrome://extensions`를 열고 오른쪽 위 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**를 눌러 이 폴더를 선택합니다.
4. 설치하면 설정 화면이 열립니다. 이후에는 확장 아이콘을 눌러 설정할 수 있습니다.

업데이트할 때는 새 파일로 교체한 뒤 `chrome://extensions`에서 이 확장의 새로고침 버튼을 누릅니다.

## 설정

먼저 학교에서 받은 OTP 메일을 열어 **보낸사람 주소**를 확인해 둡니다.

### Gmail

1. Gmail 검색창 오른쪽의 **검색 옵션** 아이콘을 누릅니다.
2. **보낸사람**에 OTP 메일 주소를 입력하고 **필터 만들기**를 누릅니다.
3. **라벨 적용**을 체크하고 **새 라벨**로 라벨을 만든 뒤(예: `otp`) **필터 만들기**를 누릅니다.
   - 라벨 이름에 띄어쓰기와 하위 라벨(`상위/하위`)은 권장하지 않습니다. 단어 구분은 `_`를 사용하세요(예: `school_otp`).
4. 확장 설정에서 **Gmail에서 OTP 읽기**를 체크하고 라벨 이름을 입력한 뒤 저장합니다.
   - Google 계정을 여러 개 쓰는 경우, Gmail 주소창 `mail.google.com/mail/u/0/`의 숫자를 **계정 번호**에 입력합니다.

### Naver 메일

1. Naver 메일 왼쪽 메일함 목록에서 **메일함 추가**로 메일함을 만듭니다(예: `otp`).
2. Naver 메일 환경설정의 메일 분류(필터)에서 규칙을 추가합니다: 보낸사람 = OTP 메일 주소 → 1번 메일함으로 이동.
3. 확장 설정에 Naver 아이디(이메일의 `@` 앞부분)와 메일함 이름을 입력하고 저장합니다. 메일함 이름은 대소문자와 띄어쓰기까지 정확히 같아야 합니다.

두 메일 모두 **이 브라우저에서 로그인된 상태**여야 합니다.

## 문제 해결

| 증상 | 확인할 것 |
|---|---|
| OTP 메일이 왔는데 채워지지 않음 | 메일을 먼저 열어보면 읽음 처리되어 대상에서 빠집니다. 안 읽은 상태로 두세요. |
| | 메일이 지정한 라벨/메일함에 들어갔는지 확인하세요. |
| | 메일이 3분 넘게 늦게 오면 사용하지 않습니다. 인증번호를 재요청하세요. |
| 설정을 바꿨는데 반영되지 않음 | OTP 화면을 새로고침하세요. |

원인을 확인하려면 아래 두 곳의 Console에서 `[OTP autofill]` 로그를 봅니다.

- OTP 화면에서 F12 → Console
- `chrome://extensions` → 이 확장의 **서비스 워커** → Console

| 로그 | 의미 |
|---|---|
| `OTP input not found` | OTP 입력칸을 찾지 못함 (포털 화면이 바뀌었을 수 있음) |
| `no fresh OTP mail yet` | 아직 조건에 맞는 메일이 없음 → 서비스 워커 로그 확인 |
| `gmail failed: 401` | Gmail에 로그인되어 있지 않거나 계정 번호가 다름 |
| `naver failed: Naver mailbox not found` | 메일함 이름이 다름 |
| `naver: no mailData in response` | Naver 응답 형식이 바뀌었거나 로그인되어 있지 않음 |
| `... unread; newest: [...]` | `ageSec`: 메일이 온 지 몇 초, `otpSubject`: 제목 형식 일치 여부 |

이슈를 올릴 때 로그를 붙여도 번호·제목·쿠키는 포함되지 않습니다. 단, 스크린샷에는 메일 내용이 찍히지 않도록 주의하세요.

## 개발

```
manifest.json   권한, 실행 범위
content.js      OTP 화면: 입력칸 찾기, 3초마다 OTP 요청, 채우기
background.js   메일 조회(Gmail Atom 피드 / Naver), OTP 추출
options.html/js 설정 화면 (확장 아이콘 팝업 겸 옵션 페이지)
settings.js     설정 기본값
test.mjs        OTP 추출·주소 검사 테스트
```

테스트 실행 (Node.js 22 이상):

```bash
node test.mjs
```

메일 제목 형식이 바뀌면 `background.js`의 `OTP_RE`를, OTP 화면 주소가 바뀌면 `manifest.json`의 `matches`와 `background.js`의 `isOtpPage`를 수정합니다.
